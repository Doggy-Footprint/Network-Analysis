## Findings

### VF01-MERMAID-UNIT — blocking evidence gap

Affected obligation: V08; parents F09,C11,Q05. Source: spec F09 (line59), V08 file-mermaid/symbol-mermaid coverage items. Evidence: `tests/test_file_analysis_cli.py:207–234`, especially assertions at232–234. Disposition: open, newly identified; no prior acceptance or mutation outcome.

Both CLI variants only require a substring `graph`; file additionally requires `main.py`. A FastAPI CLI that emits the same constant `graph TD; a["main.py"]` skeleton in both modes can satisfy these checks while ignoring selected file/symbol nodes and their relations. Direct builder Mermaid generation tests observe another surface; existing FastAPI CLI sibling checks its heading and acceptance, not selected-unit graph content. All affected declared Mermaid siblings are grouped here. This is required F09 behavior, not a request for extra Mermaid adapters.

### VF02-BOUNDARY-BROWSER — blocking evidence gap

Evidence: `tests/test_file_analysis_browser.py:10–96,99–190`; `file_analysis_browser_support.py:file_arch`; V03 package/boundary test at core60–77. Disposition: open, newly identified; no prior acceptance or mutation outcome.

The mixed fixture's source-less framework role nodes are mapped to an implementation file, not source-less boundary architecture nodes. V03 separately proves bottleneck ranking/candidate exclusion and raw conversion preservation, but cannot establish list/representative exclusion or retained exploration at the declared end-to-end browser surface. V09/V10 share the same absence and are grouped under this finding.

### VF03-CANDIDATE-SELECTION — blocking evidence gap

Affected obligation: V06; parents F08,Q01,C09,C10,A05 (F05 ownership context). Source: spec F08 (line58), approved A05 (line166). Evidence: `tests/test_file_analysis_core.py:179–232`; V03 internal-only test checks details but not candidate report.
