# 평가

> 블로그 글 이후에 진행한 내용입니다. 수치는 2026년 11월 측정 기준입니다.

AI agent가 만든다고 보고된 결함을 오픈소스 저장소 4곳(CTFd, flask-admin, ghostfolio, nowinandroid)에 일부러 넣고, 분석기가 얼마나 잡는지 재고 있습니다. 결함 유형은 연구와 보고서에서 모은 74개이고, 그중 agent 문제로 보고된 52개 유형은 가중치를 3배로 둡니다.

Sonnet이 결함을 넣고, 컴파일과 기존 테스트를 통과한 주입만 유효로 봅니다. 분석기가 주입 전후를 비교한 결과에 넣은 결함을 설명하는 항목이 있다고 Sonnet judge가 판정하면 잡은 것으로 셉니다. 같은 주입을 ruff, pylint, bandit, eslint, detekt, semgrep에도 돌려 비교했고, 결함이 없는 변경(파일 이름 변경, 포맷 정리, 주석 추가, 리팩토링)도 섞어 오탐을 확인합니다.

처음 측정에서 유효 주입 454개 중 분석기가 잡은 것은 27개였습니다. 비교 도구는 하나라도 잡은 것을 모두 합쳐 92개였습니다. 파일 이름만 바꿔도 16건 중 15건에서 오탐이 났습니다.

이후 세 번 고치면서 매번 전체를 다시 쟀습니다.

1. 파일 이름 변경을 추적하고 주석 속 이름을 관계로 보지 않게 했습니다. 이름 변경 오탐은 16건 중 2건, 주석 변경 오탐은 13건 중 0건이 되었습니다.
2. 함수 시그니처 변경과 삭제된 심볼, 아무도 호출하지 않는 메서드, NestJS에서 제공되지 않는 주입을 보고합니다.
3. 테스트가 닿지 않는 변경 코드, 약해진 테스트, 늘어난 mock을 보고합니다. 테스트를 실행하지 않고 호출 그래프와 assertion·mock 개수로 판단합니다.

지금은 454개 중 91개를 잡습니다. 처음에 어떤 도구도 잡지 못하던 7개 유형(테스트 관련 문제 5개, 불필요한 메서드, 호환성 파괴)에서는 51개 중 41개입니다.
